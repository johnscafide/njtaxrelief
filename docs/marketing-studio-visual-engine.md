# Watchdog Marketing Studio — Visual Engine 1.0

Status: production creative + handoff foundation live; provider production asset mapping intentionally gated

## Purpose

Visual Engine 1.0 is the premium-art layer for Watchdog Direct Mail. It sits between Watchdog Intelligence creative strategy and Watchdog Designs production. It may generate sophisticated campaign-level preview artwork, but it never owns postal mechanics or final print proof.

Initial provider contract remains:

- Product: postcard
- Size: 6 x 8.5 inches
- Mail class: First Class
- Watchdog customer minimum: 50 pieces
- The fulfillment provider remains the mechanical-specification and production-proof authority behind Watchdog Designs

## Customer flow

### Phase A — one-click farm setup

`Build campaign` safely automates:

1. Governed farm/audience snapshot.
2. Marketing Studio campaign creation.
3. Direct Mail recipient preflight.
4. Included Smart first concept.
5. Design routing with truthful `ready` / `partial` state.

No Phase A action can capture payment or submit an order to the provider.

### Phase B — creative quality ladder

- **Smart** — included. Clean template-assisted creative direction.
- **Signature** — paid creative service. Three Intelligence-directed concepts.
- **Studio** — paid premium creative service. Five Intelligence-directed concepts plus campaign-specific generated preview art.

Current creative fees remain server-owned in `marketing_creative_service_tiers`; provider print/postage economics remain separate.

### Phase C — production handoff

Once a Studio visual is selected:

1. Customize keeps the Watchdog artwork active instead of reverting to an older provider design.
2. The user reviews/edits copy and brand.
3. The Studio creative is explicitly approved.
4. `Prepare Watchdog Designs handoff` freezes the exact approved copy, governed Brand & Media snapshot, visual asset and 6 x 8.5 FirstClass format.
5. Watchdog stores a SHA-256 package hash in `marketing_pcm_studio_handoffs`.
6. The visual moves from `preview_only` to `awaiting_pcm_mapping`.
7. Provider asset mapping remains blocked until the exact vendor upload/slot contract is documented.
8. The authoritative production proof remains mandatory before fulfillment.

Preparing a handoff does not call a provider mutation endpoint, capture payment, buy postage or create a mailing order.

## Generated asset contract

Generated artwork is written to `marketing_intelligence_visual_assets` and private Storage bucket `marketing-intelligence-visuals`.

Each asset preserves user/campaign/brief/variant lineage, style preset, provider/model, prompt hash, private storage path, dimensions/MIME/bytes, selected state and production state. Visual Engine v2 also records the Brand & Media profile ID/version, reference asset IDs/count and whether generation used text-only or governed reference-image mode.

Clients can read only their own asset records. Browser clients do not receive generated-asset Storage upload permission. The server runtime uploads generated bytes and returns short-lived signed URLs.

### Creative state

- `generating`
- `generated`
- `selected`
- `superseded`
- `failed`

### Production state

- `preview_only`
- `awaiting_pcm_mapping`
- `mapped_to_pcm`
- `provider_rejected`

A selected Watchdog image is not a production proof and cannot bypass Watchdog Designs/provider design-proof gates.

## Runtime architecture

The Supabase project is at its Edge Function count ceiling, so image generation runs on authenticated Vercel server routes while Supabase remains the system of record for auth, asset lineage and private Storage.

The live Design transport routes image `status` and `generate` actions to:

`POST /api/marketing-studio-visual-openai-v2`

That runtime uses server-side `OPENAI_API_KEY` and the configured GPT Image model (currently `gpt-image-2`) for landscape preview generation.

Asset `styles`, `list` and `select` actions remain on:

`POST /api/marketing-studio-visual`

The combined path verifies the Watchdog Supabase session, campaign ownership and Studio entitlement, enforces generation limits, stores generated bytes privately, preserves lineage, and returns only short-lived signed URLs.

Normal users are capped at 8 generated previews per Studio brief and 2 per concept. Developer accounts have higher development limits.

## Phase E — governed Brand & Media inputs

Studio can now use the reusable Brand & Media system during generation without exposing the full media library or weakening the provider boundary.

- The saved company/display name, primary color, secondary color and neutral/background preference become sanitized campaign-level prompt context.
- Users may explicitly select **up to two** `marketing_photo` assets as Studio AI references.
- Selection is server-governed by `marketing_set_brand_studio_references`; arbitrary asset IDs, archived assets, headshots and logos are rejected.
- Reference photos remain in private `marketing-brand-media` Storage. The authenticated Brand & Media RPC resolves the user/org-accessible profile first; only then may the server use its service credential to download those exact authorized objects for the generation request.
- Headshots, brokerage logos, personal/team logos, secondary logos and brand marks remain Watchdog Designs composer inputs only. They are never sent to the background-art generator.
- With no selected reference photo, generation remains the text-to-image path.
- With one or two selected reference photos, the server uses the GPT Image reference/edit flow and sends the approved images as multipart `image[]` inputs.
- The prompt directs the model to use references only for non-literal palette, lighting, material feel and broad composition. It explicitly forbids reproducing identifiable properties, people/faces, logos, signs, addresses, readable text, house numbers or unique private details.
- The prompt hash incorporates the governed brand fingerprint and selected reference IDs. A brand/profile or reference change therefore produces different generation lineage.
- If a selected reference is archived, removed, inaccessible, invalid or over the media limit, generation fails closed and asks the user to reselect references.

### Design and Customize UX

On **Design**, Studio now shows a compact Brand Reference Media panel inside the Visual Engine. Users can select/clear up to two approved marketing photos or upload a new marketing reference directly into the same private Brand & Media profile.

On **Customize**, the full Brand & Media marketing-photo library shows which images are active Studio AI references and allows the same reference toggle. This keeps the selection reusable across campaigns while leaving creative approval/revision rules unchanged.

## Image-generation boundary

The server prompt is built only from sanitized campaign-level information such as profession, campaign objective, Intelligence creative strategy, selected concept direction, governed visual style and limited governed brand context.

It does **not** include recipient mailing lists, recipient names, mailing addresses, private CRM profiles or homeowner-level sensitive attributes.

Image prompts prohibit protected-class or demographic targeting, predicted seller intent, private distress/life-event inference, identifiable people/faces, readable house numbers/specific addresses, generated logos, QR codes, postal markings/barcodes/indicia and guaranteed property/financial/legal outcomes.

Reference-media selection does not change that rule. Uploaded reference photos are visual inputs only; their filenames, storage credentials and signed browser URLs are not used as recipient/profile context.

## Design and Customize UX

On Design:

- Studio exposes per-concept preview generation.
- Studio exposes optional governed Brand Reference Media for future generated previews.
- Every generated image is stamped `Preview · WDD proof required` in the customer-facing workflow.
- `Use concept + visual` creates/selects the matching creative draft and makes Watchdog Studio the active creative source.

On Customize:

- The exact selected Studio image stays active.
- Old provider design state no longer overrides a newer Studio selection.
- Studio revisions preserve the selected visual and become the new active creative.
- Editing/saving a revision supersedes any prior frozen handoff and requires fresh approval.
- Brand & Media changes require a new creative revision before entering a frozen production handoff.
- A 5-stage production rail shows Studio selection → creative approval → frozen handoff → Watchdog Designs mapping → production proof.

On Review:

- Studio campaigns show the frozen candidate image, package hash, launch format, mapping state and proof state.

## Production boundary

The following remain mandatory before a real Direct Mail order:

1. Selected creative exists.
2. Current Studio creative is approved.
3. Frozen Watchdog handoff exists when Studio is the source.
4. Watchdog Designs/provider design mapping exists.
5. Authoritative production proof is refreshed and approved.
6. Recipient set is current and valid.
7. Server-generated quote is current.
8. Payment is captured.
9. Explicit final launch approval exists.
10. Live provider launch gate is enabled.

Visual Engine does not invent `provider_design_id`, mark a proof approved, capture payment or enable live spend.
