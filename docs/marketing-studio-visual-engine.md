# Watchdog Marketing Studio — Visual Engine 1.0

Status: production foundation live, PCM production mapping intentionally gated

## Purpose

Visual Engine 1.0 is the premium-art layer for Watchdog Direct Mail. It sits between Watchdog Intelligence creative strategy and PCM production. It may generate sophisticated campaign-level preview artwork, but it never owns postal mechanics or final print proof.

Initial provider contract remains:

- Product: postcard
- Size: 6 x 8.5 inches
- Mail class: First Class
- Watchdog customer minimum: 50 pieces
- PCM remains the mechanical-specification and production-proof authority

## Customer flow

### Phase A — one-click farm setup

`Build campaign` now performs the safe setup work that can be automated without charging or mailing:

1. Create governed farm/audience snapshot.
2. Create the Marketing Studio campaign.
3. Preflight Direct Mail recipient addresses.
4. Generate the included Smart first concept.
5. Open Design with a truthful `ready` or `partial` setup state.

Failures in recipient preflight or first-concept generation do not destroy the saved farm. The Design page tells the user which setup step needs review.

No Phase A action can capture payment or submit an order to PCM.

### Phase B — creative quality ladder

- **Smart** — included. Clean template-assisted creative direction.
- **Signature** — paid creative service. Three Intelligence-directed concepts with richer editorial/procedural visual treatment.
- **Studio** — paid premium creative service. Five Intelligence-directed concepts plus campaign-specific generated preview art.

Current creative fees remain server-owned in `marketing_creative_service_tiers`; provider print/postage economics remain separate.

## Generated asset contract

Generated artwork is written to `marketing_intelligence_visual_assets` and private Storage bucket `marketing-intelligence-visuals`.

Each asset preserves:

- user
- campaign
- Intelligence creative brief
- variant index
- style preset
- provider/model
- sanitized prompt + prompt hash
- private storage path
- dimensions / MIME / bytes
- selected state
- production state
- optional creative binding

Clients can read only their own asset records. Browser clients do not receive Storage upload permission. The server runtime uploads generated bytes and returns short-lived signed URLs.

## Asset state model

### Creative state

- `generating`
- `generated`
- `selected`
- `superseded`
- `failed`

### Production state

- `preview_only`
- `awaiting_pcm_mapping`
- `mapped_to_pcm`
- `provider_rejected`

**Visual Engine 1.0 generates only `preview_only` artwork.** A selected Watchdog image is not a PCM proof and is not eligible to bypass PCM design/proof gates.

## Runtime architecture

The Supabase project is currently at its Edge Function count ceiling. Visual generation therefore runs through authenticated Vercel endpoint:

`POST /api/marketing-studio-visual`

Supported actions:

- `status`
- `styles`
- `list`
- `generate`
- `select`

The endpoint:

1. verifies the Watchdog Supabase session;
2. verifies Marketing Studio access;
3. verifies campaign ownership;
4. requires Studio creative and the applicable paid-plan entitlement for generated art;
5. enforces generation limits;
6. generates through Vercel AI Gateway;
7. uploads to private Supabase Storage with the service role;
8. records lineage and a `preview_only` production state;
9. returns only a short-lived signed URL.

Normal users are capped at 8 generated previews per Studio brief and 2 per concept. Developer accounts have higher development limits.

## Image-generation boundary

The server prompt is built only from sanitized campaign-level information:

- profession
- campaign objective
- Intelligence creative strategy
- selected concept visual direction
- governed visual style preset
- limited brand context

It does **not** include the recipient mailing list, recipient names, mailing addresses, private CRM profiles or homeowner-level sensitive attributes.

Image prompts explicitly prohibit:

- protected-class or demographic targeting
- predicted seller intent
- private distress or life-event inference
- foreclosure/distress imagery
- identifiable people/faces
- readable house numbers or a specific address
- generated logos
- QR codes
- postal markings, barcodes or indicia
- guaranteed property values, savings, legal outcomes, financing outcomes, profit or response rates

The generated file is intended as background/hero artwork. Copy, branding, QR/tracking and postal mechanics remain separate layers.

## Design UX

On the Design step:

- Smart concepts retain a restrained professional visual treatment.
- Signature concepts receive richer editorial/data-style procedural presentation.
- Studio exposes Visual Engine style selection and per-concept preview generation.
- Every generated image is visibly stamped `Preview · PCM proof required`.
- `Use concept + visual` creates/selects the matching creative draft and binds the chosen visual before moving to Customize.
- `Use concept without generated art` remains available.

The chosen asset is also written into campaign settings as a recoverable pointer.

## PCM boundary

The following remain mandatory before a real Direct Mail order:

1. Selected creative exists.
2. Watchdog/PCM design mapping exists.
3. PCM authoritative proof is refreshed and approved.
4. Recipient set is current and valid.
5. Server-generated quote is current.
6. Payment is captured.
7. Explicit final launch approval exists.
8. Live PCM launch gate is enabled.

Visual Engine does not change `provider_design_id`, mark a proof approved, capture payment or enable live spend.
