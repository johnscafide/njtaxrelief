# Mobile push notifications (source only)

These pieces let the Watchdog mobile app register a device for push
notifications and let the server send a push when a Property Pulse event is
written for that member. They are committed as source under the Git-first
deployment policy (`supabase/functions/DEPLOYMENT-POLICY.md`). Nothing is
deployed, applied, or switched on by merging them.

## What is here

- `supabase/migrations/20260930090000_push_device_registrations.sql`
  - `public.push_settings`: kill switch, `enabled` defaults to `false`.
  - `public.push_device_registrations`: one row per device install. Raw FCM
    tokens live here and are service-role only; browser roles have no grants.
  - `public.get_my_push_devices()`: the only user-callable read, token-free.
  - `public.push_outbox` with `claim_push_outbox`, `complete_push_outbox`,
    `defer_push_outbox`, `invoke_push_sender`, `verify_push_worker`, and the
    `private.push_runtime` worker URL/token singleton.
  - `trg_push_property_event` on `property_update_events`: queues one push per
    active device with alerts on, honoring the per-property pause, the event's
    `minimum_plan`, and the device's quiet hours (deferred, not dropped).
  - pg_cron job `watchdog-push-sender` every minute; it returns at once when
    push is off or nothing is due.
- `supabase/functions/push-device-register/index.ts` (`verify_jwt = true`):
  actions `register`, `heartbeat`, `update`, `unregister`, `list`. Responses
  never include the token.
- `supabase/functions/push-sender/index.ts` (`verify_jwt = false`, worker
  token checked inside): claims outbox rows and sends FCM HTTP v1 messages.
- `property/tests/push-notifications-contract.mjs`
  (`npm run test:push-notifications`): repository-side invariants.

Push content comes only from `property_update_events.title`, `summary`,
`pams_pin`, `event_type`, `severity` and `minimum_plan`. No owner field,
mailing-address field, CRM contact field, or parcel ZIP is ever part of a push.

## Secrets (Edge Function environment only)

- `FCM_PROJECT_ID`: the Firebase project id.
- `FCM_SERVICE_ACCOUNT_JSON`: the full Google service-account key JSON with
  the Firebase Cloud Messaging API enabled. The sender mints its own OAuth2
  access token from it (scope `firebase.messaging`). Never put it in browser
  JavaScript, the app, or Git.
- Standard: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (or
  `SUPABASE_SECRET_KEYS`).

The worker token is generated by the migration in `private.push_runtime` and
is read by pg_cron only; it is not an Edge Function secret.

## Deployment checklist (from the design proposal, section 8.6)

1. Commit the migration, both `index.ts` files, and the `[functions.*]`
   entries in `supabase/config.toml` (done in this change).
2. Apply the migration manually (SQL editor or `supabase db push`). Confirm
   `select enabled from public.push_settings` is `false`.
3. Deploy `push-device-register` (`verify_jwt = true`) and `push-sender`
   (`verify_jwt = false`). Set `FCM_PROJECT_ID` and `FCM_SERVICE_ACCOUNT_JSON`
   as function secrets.
4. Verify each deployed version, SHA-256 fingerprint and `verify_jwt` against
   the committed source, then record both functions in
   `supabase/functions/PRODUCTION-INVENTORY.json` as `source_snapshot`.
5. Only then confirm `private.push_runtime.worker_url` (seeded to the
   production `push-sender` URL) and set `push_settings.enabled = true`.

Until step 5 is complete nothing is sent: the trigger returns without queueing
while `push_settings.enabled` is false, `invoke_push_sender()` does not call
the worker, and the worker itself answers `push_configured: false` while the
FCM secrets are missing.

## Switching off

`update public.push_settings set enabled = false, updated_at = now() where singleton;`
stops new pushes immediately. Queued rows stay in `push_outbox` and are not
sent while the switch is off.
