# Design and Voice Guide (NJPropertyTaxRelief.com)

This is a standing set of rules. Follow these on top of whatever project brief you're given. If anything in a project prompt conflicts with this file, this file wins on design and copy mechanics.

## Color

- Keep the current color scheme as it exists in the codebase right now. Do not introduce new colors, additional accent colors, or a broader palette just because it looks more "designed."
- No gradients. If you see one in the current code, remove it. A gradient is not a middle ground here, it counts as extra color.
- No multi-color combinations that don't have a clear functional reason (like a status system: red for error, green for success). Decorative multi-color choices are not allowed.
- If you genuinely believe a different color or a small adjustment to the existing scheme would meaningfully improve the site, you can propose it, but only with specific reasoning: why the current color underperforms, what the change fixes (contrast, readability, trust, accessibility), and what evidence or principle backs it up. No proposing a change just for the sake of variety or trend. Default assumption is the current scheme stays.

## Shadows and grid layouts

- No box shadows used as dividers or separators in grid layouts. If a grid needs separation, use spacing, a thin single-color border, or background contrast, not a shadow effect.
- Shadows in general should be used sparingly if at all. If you're not sure whether a shadow is necessary, leave it out.

## Icons

- No emojis anywhere on the site. Not in UI, not in copy, not in error states, nowhere.
- Icons must come from Flaticon.
- Every icon used has to be justified. That means: what is this icon communicating that text alone doesn't, and why this specific icon. If you can't answer that clearly, don't use an icon there.

## Copy

- No em dashes. Ever. Rewrite the sentence instead.
- Every sentence needs to earn its place. Do not pad paragraphs to make a section look more complete or more thorough. If a point can be made in one sentence, make it in one sentence.
- Context and clarifying notes are fine and often necessary, especially for tax program rules where people need the details to trust the answer. The line is between context that helps someone understand their situation, and filler that just adds word count.
- Do not create a blog or long-form content section by default. Only create one, and only add an entry, if a topic genuinely needs more depth than the main pages can hold, something like a full walkthrough of a specific program change or a detailed FAQ that would clutter the main calculator pages. If you do write blog content, it has to match the voice below exactly. Don't let it drift into a more "articley" or generic tone just because it's longer form.

## Voice and tone

Match John's existing voice across the site and his other content (TikTok, tax content, site copy already written): direct, conversational, no corporate polish, no buzzwords, explains things plainly like you're talking to someone who's confused and just wants a straight answer. No em dashes, ever, in any written content on this site. Avoid hedging language and avoid sales language. If a sentence sounds like it belongs in a brochure, rewrite it.

When in doubt on tone, read a few paragraphs of existing copy on the live site before writing anything new, and match that rhythm and word choice rather than defaulting to a generic "helpful assistant" tone.
