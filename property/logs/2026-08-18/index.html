Watchdog Analyst as the universal interface

ACTIVE · INTENT QUESTIONING LIVE ON HOME

Implementation is governed by the White Paper doctrine: profession is only a lens; active job-to-be-done is learned through an auditable Intent Engine rather than assumed from a role or a single behavior.

  • Production intelligence_intent_states stores owner-scoped current Context Graph state: profession, active job, confidence, competing intents, evidence references, confirmed fields, assumptions, missing questions, property scope, source freshness, and meaningful-update time.
  • Append-oriented intelligence_intent_events reconstructs observations, hypotheses, questions, answers, corrections, intent changes, analyses, actions, and outcomes while classifying observed, derived, hypothesis, user-confirmed, assumption, and missing-evidence records.
  • Both tables use RLS and owner-only authenticated policies; anonymous access is revoked. Event rows intentionally have no client update/delete grant so normal signed-in clients cannot rewrite the decision trail.
  • Property Home now loads a dedicated governed Intent Context runtime. A property open is logged once per signed-in user/property/session as an observed event, not interpreted as intent by itself.
  • If no job-to-be-done has been confirmed for the property, Watchdog creates profession-aware competing job candidates as hypotheses and records the missing question instead of silently selecting a job.
  • The UI asks one high-information-gain question: what the user is trying to accomplish with the property. Real-estate choices distinguish buyer representation, listing farming, listing preparation, investment research, and another objective. Other professions receive their own materially different job choices.
  • User selection is persisted as active_job at 100% confidence only because the user explicitly confirmed it. The answer and resulting intent update are appended separately to the decision trail.
  • Users can change the research context. That action clears the confirmed job, records a correction event, and reopens the discriminating question rather than hiding the prior decision path.
  • The runtime emits watchdog:intent-updated so other Intelligence surfaces can consume the confirmed context without scraping UI text.
  • The listing-farm path explicitly frames outputs as evidence-backed conversation opportunity and prohibits assuming homeowner seller intent.
  • Dedicated responsive Intent Context styling and loader wiring use stable asset URLs with no ?v= query parameters.
  • The existing Analyst CI contract was expanded to syntax-check the new runtime and enforce state/event persistence, hypothesis-vs-fact boundaries, user-confirmed intent, 100%-confidence constraints, seller-intent safety language, session observation dedupe, event publication, CSS presence, and stable asset loading.
  • Production Vercel deployment for commit d74a9b363ce435a176fc42b8dc35da16c82514f8 reached READY. The production watchdog-intent-context.js asset was fetched successfully over HTTPS with HTTP 200.
  • Linear NJW-203 received a production implementation note tying the adaptive Intent Context extension back to the shared page-native Intelligence runtime.
  • Next step inside #2: consume confirmed active_job inside Analyst analysis itself and extend the same Context Graph/question contract to watchlists and other universal entry points, where multi-property observations can create competing hypotheses without becoming facts.
