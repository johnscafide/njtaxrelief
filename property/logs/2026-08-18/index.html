Visible Watchdog Data Graph moat

COMPLETE · PRODUCTION

Property Home now exposes the governed chain that creates Watchdog's moat instead of reducing it to a marketing claim: registry → selected property context → source lineage → deterministic derived signals → persisted Intelligence models/findings → governed actions.

  • The graph lazy-loads near the viewport and uses the authenticated intelligence-semantic-context contract. It requests a bounded cross-domain view and does not make Property Home hydrate the graph before the user approaches it.
  • The governed registry universe is displayed separately from the number of marker definitions selected for this property and the number that actually resolved as available. Registry size is explicitly not represented as property-level evidence.
  • Only semantic markers whose state is actually available count as resolved property data. Planned, missing, stale, provider-missing or unentitled definitions remain outside that count.
  • Source-family counts are derived from resolved marker lineage; source facts/references, trusted observations, deterministic derived signals and other resolved values remain separate truth classes.
  • The graph exposes preserved source-conflict count, source-authority policy version and semantic snapshot contract rather than hiding the governance layer.
  • Model and finding counts come from persisted, RLS-visible intelligence_runs and intelligence_findings lineage. Action counts come only from persisted recommended_actions; no action count is invented from UI copy.
  • Failure mode is fail-honest: when governed Semantic Context cannot resolve, Watchdog shows a retry state and explicitly refuses placeholder counts.
  • The component follows Watchdog Analyst Intel inside the Property Home story, owns the full content width, provides an expandable source/truth/integrity inspector, and has responsive desktop/mobile treatment.
  • Concurrent sprint work was reconciled into one authoritative watchdog-data-graph-contract.mjs in Access Boundary CI; the duplicate contract was removed. The contract syntax-checks the runtime and enforces truthful counting, source/derived separation, persisted lineage, lazy loading, placement, inspection state and the no-?v= rule.
  • Phase 8 semantic-context documentation was reconciled with the August 18 production launch and now documents the production Data Graph rule instead of falsely saying the semantic system is staging-only.
