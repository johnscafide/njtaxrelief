# Watchdog Mobile Audit — Run 050

**Timestamp:** 2026-08-21 22:36 ET  
**Page:** `/property/marketing-studio/admin/`  
**Area audited:** Direct Mail Analytics admin async period/segment updates, initialization failure recovery, mobile status feedback, header/safe-area controls

## Finding
The current analytics runtime awaited period and segment RPC refreshes without a mobile busy state or user-visible completion/failure feedback. If an interaction failed, the promise could reject while leaving the user with no clear explanation. More seriously, every initialization/RPC failure rendered the same `Developer access required` state even when the actual cause could be a transient analytics/network failure. This was a substantive mobile functionality and certification risk because the user could not distinguish access denial from recoverable loading failure or retry the screen in place.

## Typography/readability assessment
The recovery and async status layer needed to meet the current Watchdog mobile baseline rather than inherit compact admin microcopy. Mobile status/toast text is now 14px, recovery body copy 15px, recovery heading 20px, retry text 15px, and search/select controls are explicitly 16px. Primary navigation and retry targets are 44–48px minimum.

## Preserve vs. redesign decision
Preserve the existing analytics data model, RPCs, period controls, customer segments, and desktop presentation. Redesign only the mobile feedback/recovery layer. The prior valid analytics view remains visible when a period/segment refresh fails; the mobile experience reports the failure instead of replacing useful data or introducing a second data path.
