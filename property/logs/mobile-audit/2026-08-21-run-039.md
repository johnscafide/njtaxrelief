## Finding

The prior Recipients passes had already converted the production table to mobile review cards and corrected search/filter/touch density, but three certification risks remained:

1. `marketing_direct_mail_recipient_page` / summary failures rendered only `Recipient review unavailable: …` text. Mobile users had no direct retry action.
2. A zero-result search/filter rendered only `No recipients match this view.` with no one-tap reset path.
3. Include/Exclude disables the action while its RPC runs, but the phone UI provided no explicit busy state. The adjacent mailing estimator also inherited desktop-density labels (11px) and controls because the authoritative quantity is injected/read-only only after recipient summary resolution.

## Typography/readability assessment

The estimator is decision-critical because it shows authoritative recipient quantity, provider estimate, Watchdog retail estimate and gross-profit context. It should not be treated as desktop microcopy. On mobile, form labels and estimate labels are now 12–14px, primary explanation text 15px, fields/selects 16px, and the Prepare action is 15px on a 48px target. Quantity remains authoritative/read-only once recipient summary data is available.

## Preserve vs redesign decision

- **Recipient evidence/recovery:** preserve the existing card presentation and RPC data path; add mobile-native recovery controls to the empty/error card instead of creating a second data workflow.
- **Include/Exclude:** preserve the existing mutation RPC and rerender behavior; add a mobile-only `Including…` / `Excluding…` busy state and `aria-busy` feedback rather than changing campaign logic.
- **Mailing estimator:** preserve the estimator and all financial context because it is meaningful workflow information; re-scale and stack it for mobile instead of hiding or truncating it.
