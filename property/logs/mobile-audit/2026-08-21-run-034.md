## Page 1 — `/property/marketing-studio/audience/`

### Area audited
Final route-wide mobile certification pass: bootstrap/loading failure behavior, empty states, long dynamic content, narrow-phone overflow, and previously audited critical interactions.

### Finding
The Audience hub bootstrap can return early when campaign context is unavailable and catches initialization failures only in the console. On mobile, that can leave users indefinitely on `Opening Marketing Studio…` with no recovery action. Dynamic source/smart-audience cards also needed explicit `min-width:0`, wrapping, and readable empty-state treatment to prevent long labels or campaign-derived content from creating narrow-phone overflow.

### Typography/readability assessment
Operational mobile typography from Runs 031–033 already met the strengthened baseline for inputs, labels, suggestions, map/saved-area controls, and navigation. Run 034 raised the remaining loading/empty/recovery surfaces to 12–15px supporting/body text with a 20px recovery heading and a 48px / 15px primary action.

### Preserve vs redesign decision
Preserve the Audience information architecture. The failure state, however, should not remain a desktop-style indefinite spinner. On phones it is redesigned into a clear recovery card with an explicit retry action and safe-area-aware spacing.

### Change
- Added a mobile-only 9-second bootstrap recovery guard to `marketing-studio-audience-mobile-a11y.js`.
- If the Audience surface never materializes and the loading indicator remains, mobile now presents an accessible `role="alert"` recovery state with a 48px `Retry Audience` action.
- Retry performs a safe reload and explicitly states that saved campaign data is not modified.
- Hardened Audience mobile containers/cards/empty states with `min-width:0`, `max-width:100%`, `overflow-wrap:anywhere`, and readable empty/loading typography.
- No shared desktop Audience bootstrap logic was altered.

### Verification evidence

- Existing Audience route loads both mobile audit layers only at `max-width:720px` and declares `viewport-fit=cover`.

### Desktop-isolation result
**PASS.** CSS is loaded only at `<=720px`; the behavior shim exits immediately above `720px`. Desktop Audience runtime and styling are unchanged.

### Certification status
**MOBILE CERTIFIED — source-review level.** Runs 031–034 collectively cover primary form/input sizing, mode controls, autocomplete touch and keyboard behavior, saved areas, map controls/popups, sticky navigation/safe areas, loading/empty/error recovery, long-content overflow, readable typography, and critical Audience interactions.

## Page 2 — `/property/marketing-studio/audience-review/`

### Area audited
Initial mobile deep dive: audience decision table, filters, filter modal/panel controls, search/sort inputs, insights, bulk actions, property detail controls, and pagination.

### Finding
Audience Review was responsive in broad layout but remained desktop-dense on phones. Source showed 9–10px operational labels/insight text, 12px filter inputs, a 34×34 filter close control, 16×16 table checkboxes, a 32×32 property-detail close control, 38px pagination controls, and a 1420px evidence table. The table was contained by overflow, but its typography/touch targets were not mobile-grade.

### Typography/readability assessment
This was a substantive certification failure. The decision surface contains address, assessment, tax, sale, Watchdog, and filter data, so the 9–12px operational typography could not be treated as decorative microcopy. Mobile inputs now use 16px text, supporting labels generally 12–14px, property/data values 13–14px, and critical actions 13–15px.

### Preserve vs redesign decision
Preserve the evidence-rich table because removing columns would hide decision-critical property data. Redesign its mobile presentation as a deliberate component-contained horizontal scroller with a reduced 1120px working width, sticky selection column, larger table text, 22px checkboxes, and 44px inspection controls. The filter/detail layers remain stacked but are enlarged to mobile-native targets.

### Change
Created `property/css/marketing-studio-audience-review-mobile-audit.css`, loaded only at `<=720px`, with:
- 16px / 48px search, sort, and filter inputs.
- 44–48px filter, chip, reset/apply, bulk, inspect, detail-dismiss, and pagination controls.
- 12–14px filter labels/supporting copy and 14px explanatory copy.
- 12px insight/summary labels with 18px values.
- Contained horizontal evidence table with overscroll containment, 11px headers, 13–14px row text, 22px checkboxes, and sticky first selection column.
- Narrow-phone one-column insights/detail grids and stacked filter actions at `<=420px`.
- Explicit focus-visible treatment.
- Added `viewport-fit=cover` to Audience Review.
