# Watchdog Mobile Audit — Run 026

**Timestamp:** 2026-08-20 22:33 ET  
**Page:** `/property/marketing-studio/customize/`  
**Area audited:** Brand/media asset panel inside Marketing Studio Customize, including upload controls, asset metadata, library thumbnails, destructive actions, form typography, narrow-phone asset layout, and touch target sizing.

## Finding

The Customize workspace had a material mobile certification risk in the brand/media surface. The underlying desktop stylesheet still used 8.5–10px operational text for asset metadata, upload controls, section copy, and empty-state text. Asset action buttons were only 30×30px and library thumbnail delete buttons were only 22×22px. These are not decorative labels: they control image/logo uploads, media-library management, and asset removal inside a production workflow.

On a phone, the panel technically fit after its existing responsive breakpoint, but its controls remained miniature desktop UI and required overly precise tapping.

## Typography/readability assessment

**Failed before change.** Core brand/media controls were below the current Watchdog mobile typography baseline. Operational labels in the 8.5–10px range and 22–30px destructive/action targets are too small for reliable mobile use.

After the change:

- hero explanation is 15px;
- status text is 12–13px;
- section labels and descriptions are 12–13px;
- form labels are 13px;
- form inputs/selects are 16px with 48px minimum height;
- asset names and metadata are 12–13px;
- upload/action controls are 13px with 44px minimum touch targets.

## Preserve vs. redesign decision

- **Preserve:** the existing brand/media information architecture, upload semantics, asset cards, library thumbnails, form fields, and desktop layout.
- **Redesign for mobile:** enlarge the media-management controls and typography, allow long asset metadata to wrap rather than truncate, enlarge destructive/thumbnail actions to finger-safe targets, and collapse media/library grids to one column at <=420px. The workflow remains complete; no asset-management capability is hidden on mobile.

## Change

Updated the mobile-only `property/css/marketing-studio-mobile-audit.css` layer.

Mobile changes include:

- Brand/media hero copy raised to a 21px title and 15px supporting text;
- status block raised to 12–13px and given a 48px minimum row height;
- section labels/descriptions raised to 12–13px;
- form labels raised to 13px;
- inputs, selects, and textarea controls set to 16px text with 48px minimum height to improve readability and avoid iOS focus zoom behavior;
- save/help copy raised to 12px;
- upload buttons, asset-action buttons, and thumbnail delete buttons now have 44×44 minimum touch targets with `touch-action: manipulation`;
- asset names use 13px and asset metadata 12px;
- metadata may wrap safely with `overflow-wrap:anywhere` instead of being forced into an 8.5px ellipsis;
- asset header icons are raised to 44×44;
- at <=420px, asset and media-library grids collapse to one column and primary upload/save actions become full-width.

## Verification evidence

Source re-read after the write confirms:

1. The original brand/media stylesheet still contains the desktop values that motivated the failure: 8.5–10px metadata/upload text, 30×30 asset actions, and 22×22 thumbnail delete controls.
2. `property/css/marketing-studio-mobile-audit.css` now overrides those controls at mobile widths with 12–16px operational typography, 44px+ critical touch targets, 48px form controls, metadata wrapping, and a single-column narrow-phone presentation.
3. `/property/marketing-studio/customize/index.html` still loads `marketing-studio-mobile-audit.css` only with `media="(max-width: 700px)"`.
4. No desktop stylesheet, desktop JavaScript, approval semantics, print-art geometry, auth, billing, campaign data, or Supabase schema/data was changed.

## Desktop-isolation result

**PASS.** All Run 026 changes live in the dedicated Marketing Studio mobile audit stylesheet, which the Customize route loads only at viewport widths <=700px. The one-column asset/grid treatment is further restricted to <=420px. Desktop presentation and creative artifact geometry remain unchanged.
