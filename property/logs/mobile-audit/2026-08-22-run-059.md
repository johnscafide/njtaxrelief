# Watchdog Mobile Audit — Run 059

**Timestamp:** 2026-08-22 06:38 ET  
**Page:** `/property/data-center/`  
**Area audited:** Mobile shell/filter presentation; governed marker catalog; typography/readability; touch targets; horizontal overflow strategy; safe-area behavior

## Finding
The current Data Center mobile breakpoint only stacked the desktop filter rail. The core governed marker catalog remained a 1,050px-wide seven-column desktop table with operational text commonly 8–11px, 15px checkboxes, single-line marker IDs/titles, truncated professional-fit tags, and a horizontal-scroll requirement for every row. That technically kept the page from breaking, but it failed the strengthened Watchdog mobile standard because the primary selection workflow was still a compressed desktop ledger rather than a phone-appropriate interface.

The Data Center route also lacked `viewport-fit=cover`, so the route could not reliably use device safe-area insets on modern iPhones.

## Typography/readability assessment
Before this run, the active 2027 Data Center layer used roughly 8–11px text for table metadata, pills, professional tags, filter labels, selected-field chips, result controls, and footnotes. On phones, this is below the expected SaaS-mobile baseline for operational UI. Primary filter fields were 12px despite being core form controls.

The new mobile layer brings primary body/explanation copy to 15px, form controls to 16px, marker names to 16px, row values to 14px, supporting IDs/labels/tags to 11–13px, and selected-field/control text to 13–14px. Important actions are 44–48px minimum touch targets.

## Preserve vs. redesign decision
Preserve every governed marker field and the existing catalog/filter/data semantics because these are core Data Center functionality. Do not hide columns or remove professional/tier/origin context.

Redesign the marker catalog presentation on phones. At `<=720px`, the desktop table becomes stacked marker review cards using the existing row markup and existing selection checkbox. Each card exposes Marker, Category, Scope, Plan, Origin, and Professional fit as explicit labeled values, eliminating page-level horizontal panning while preserving all information.

Preserve built result sheets as actual tables because arbitrary selected columns are intrinsically tabular. Their horizontal scroll is contained inside the result module rather than being allowed to drive page-level overflow.
