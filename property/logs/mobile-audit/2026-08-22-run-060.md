# Watchdog Mobile Audit — Run 060

**Timestamp:** 2026-08-22 07:34 ET  
**Page:** `/property/data-center/`  
**Area audited:** Saved views; result-builder gating; schedule/delete workflow; mobile dialogs; async feedback; focus behavior; typography; safe areas

## Finding
Data Center's current saved-view and delivery workflows still relied on native browser `prompt()`, `confirm()`, and `alert()` dialogs. On mobile those dialogs bypass Watchdog's typography and touch system, provide no controlled safe-area presentation, and make focus/validation behavior inconsistent. The same native-alert path was also used when Build Sheet had no selected fields.

## Typography/readability assessment
The native browser dialogs could not be certified against Watchdog's mobile typography baseline because their text, controls, spacing, and focus treatment are browser-controlled. The replacement mobile sheet uses a 22px heading, 15px explanatory copy, 13px field labels, 16px form controls, 15px action text, and 44–48px touch targets. Transient success/error feedback uses 14px text.

## Preserve vs. redesign decision
Preserve the existing saved-view, delivery-job, field-selection, filter, scope, and Supabase table semantics. Redesign only the phone interaction layer: at `<=720px`, Save view, Schedule, Delete view, sign-in-required messaging, and zero-selection Build Sheet feedback use a Watchdog bottom sheet/status surface. Desktop continues using the existing runtime behavior unchanged.
