# Watchdog Mobile Audit — Run 062

**Timestamp:** 2026-08-22 09:33 ET  
**Page:** `/property/data-center/`  
**Area audited:** startup/loading/error recovery; mobile retry affordance; failure-state typography; focus/reachability; desktop isolation

## Finding
Data Center still had a substantive mobile certification risk in its initial catalog bootstrap. If `/property/data/marker-registry.json` failed, the authoritative runtime replaced the catalog body with only `Marker registry could not load.` and logged the error. There was no recovery action. A slow or hung startup could also leave the route indefinitely unresolved with placeholder totals and an empty catalog. On mobile this was a dead end even though the underlying failure could be transient.

## Typography/readability assessment
The new recovery presentation follows the current mobile SaaS baseline rather than exposing a compact table error: 20px recovery heading, 15px explanatory copy with 1.55 line-height, 11px nonessential kicker, and a 15px Retry label on a 48px full-width primary action. No important recovery text falls into the 8–10px operational range.

## Preserve vs. redesign decision
Preserve the authoritative Data Center startup/runtime and provider path. Do not create a mobile-specific catalog fetch or alternate data source. Redesign only the failed/stalled mobile presentation: replace the passive error row with a readable recovery card and Retry action that reloads the same authoritative route.

## Change
- Added `property/js/data-center-mobile-recovery.js`; it exits immediately above 720px or outside the Data Center route.
- Detects the authoritative runtime's `Marker registry could not load` failure through the existing `#dc-rows` surface.
- Adds a bounded 10-second unresolved-startup safeguard so a hung catalog bootstrap also becomes recoverable.
- Displays an accessible recovery region with `role="alert"`, assertive live semantics, a full-width `Retry Data Center` action, and focus movement to the recovery action.
- Retry exposes `aria-busy`, changes to `Retrying…`, and reloads the same route so the existing marker-registry/provider path is retried unchanged.
- When the normal `watchdog:data-center-ready` event fires, the recovery timer is cleared and the normal catalog remains authoritative.
- Added `property/css/data-center-mobile-recovery.css`, loaded only at `<=720px`, for readable recovery typography and 48px touch sizing.
- Wired both assets into `/property/data-center/index.html` after the existing mobile audit/results layers and after the authoritative Data Center runtime.
