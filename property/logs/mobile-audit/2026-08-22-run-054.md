# Watchdog Mobile Audit — Run 054

**Timestamp:** 2026-08-22 01:38 ET  
**Page:** `/property/agent-desk/` — Agent Control  
**Area audited:** Opportunity queue/search/sort controls and property-opportunity card actions

## Finding
Agent Control still had a substantive mobile workflow risk after Run 053. The current 2027 layer compresses queue tabs and search/sort controls to roughly 9–10px desktop-density UI, while the card action row inherits a wrapping desktop flex presentation. The existing readability pass raises many buttons to a 48px mobile touch floor, but the decision-critical `Record outcome` select (`.ad-outcome`) was not part of that mobile touch-size rule and had no deterministic mobile height/font baseline. On narrow phones the full action set could also wrap into an irregular control cluster that is harder to scan and tap.

## Typography/readability assessment
Queue/search/sort and opportunity-card controls are operational UI, not captions. They should follow the mature SaaS mobile baseline rather than the 9–10px values in the desktop-density layer. Run 054 uses 14px queue/action labels, 16px search/sort/outcome fields, 15px property reasoning copy, 14px address text, 12px metadata, and 18px card headings with comfortable line-height.

## Preserve vs. redesign decision
Preserve the five queue states because each state is useful and directly actionable, but present them as a finger-safe horizontally scrollable/snap row rather than shrinking or hiding labels. Preserve search and sort as a paired command row on normal phones, stacking them on <=420px devices.

Preserve every opportunity action and the authoritative outcome selector. Re-present the action cluster as a two-column mobile grid, collapsing to one column on <=420px phones, instead of retaining the wrapping desktop flex row. This keeps all functions reachable without making any decision control miniature.

## Change
- Extended `property/css/agent-control-mobile-audit.css` inside its existing mobile/tablet breakpoints only.
- Queue control surface is no longer sticky on phones; it becomes a normal-flow single-column command surface, reducing stacked-sticky viewport loss beneath the Agent Control work navigation.
- Queue tabs use 48px minimum height, 14px labels, horizontal snap scrolling and contained overscroll.
- Search/sort now use 16px fields with deterministic 48px height; below 420px they stack to full width.
- Opportunity card heading/reason/address/metadata typography now follows the mobile readability floor.
- Opportunity actions are a two-column 48px/14px grid; below 420px they become full-width one-column actions.
- `Record outcome` now has an explicit 48px minimum target and 16px select text, closing the previous touch/readability gap.
- Long addresses can wrap safely rather than creating card-level overflow.
- Added visible focus treatment for queue, search/sort and card action controls.
