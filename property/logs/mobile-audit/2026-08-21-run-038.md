**Area audited:** Recipient validation/search, production recipient list, selection controls, typography, overflow, pagination

## Finding

The recipient production list still inherited a desktop-first five-column table with a `min-width: 780px`. On phones this forced repeated horizontal scanning across recipient/property, mailing address, validation, source, and include/exclude actions. The same surface used 9px table headers/status chips, 10–11px row/action text, 12px search text, and 7–10px pagination/filter controls in the base production workspace CSS.

This was a substantive mobile certification risk because the list is an operational review surface used to decide exactly who will be mailed. A horizontal scroller would technically expose all fields, but it would make recipient-by-recipient validation unnecessarily difficult and would preserve desktop information architecture instead of adapting it to the phone.

## Typography/readability assessment

**Before:** operational recipient-review text ranged roughly 9–12px, with 10px include/exclude actions and 12px search input text. This is below the current Watchdog mobile SaaS baseline for repeated operational reading and creates an iOS focus-zoom risk for the search field.

**After:** recipient row values are 14px, supporting/property-key text 12px, status chips 12px, field labels 12px, filter/action text 14px, search/page-size controls 16px, count text 13–18px, and pagination copy 13px. Long property keys, addresses, exclusion reasons, and source text can wrap safely.

## Preserve vs redesign decision

**Redesign for mobile.** The desktop table remains appropriate on large screens and is unchanged. On `<=720px`, the same table markup is restyled into vertically stacked recipient review cards. Every original field and include/exclude action remains available; no recipient evidence is hidden. This is preferable to a phone-width horizontal table because users can review one recipient completely without lateral panning.
