# Watchdog Mobile Audit — Run 027

**Timestamp:** 2026-08-20 23:35 ET  
**Page:** `/property/marketing-studio/customize/`  
**Area audited:** Watchdog Designs creative canvas zoom controls and narrow-phone inspection behavior.

## Finding

The Customize workspace intentionally preserves the postcard's real production geometry and presents it inside a contained mobile pan/zoom surface. However, the production-v2 runtime still enforced the same 70% minimum zoom on mobile that it uses on desktop.

That created a mobile usability/certification risk: the mobile audit layer uses a 560px creative canvas (520px at <=420px) so designed postcard text remains inspectable instead of being permanently crushed. At the old 70% minimum, a 520px canvas still rendered at roughly 364px before surrounding canvas padding. On narrow phones, users therefore could not zoom far enough out to obtain a useful whole-piece overview and were forced to pan horizontally even at the minimum zoom.

## Typography/readability assessment

**Pass with preserved-art exception.** Editor chrome and operational controls already use the Watchdog mobile typography baseline from Runs 024–026. The postcard itself is a production artifact whose internal typography/geometry must not be rewritten merely to fit the phone viewport.

The correct mobile treatment is therefore to preserve the artifact at authentic geometry while giving users both a readable inspection zoom and a sufficiently zoomed-out overview state.

## Preserve vs. redesign decision

- **Preserve:** postcard dimensions, front/back geometry, creative content, print typography, desktop zoom range, and existing pan/zoom interaction model.
- **Redesign for mobile:** make the zoom bounds responsive. Mobile can now zoom down to 60% and is capped at 120%, while desktop retains its original 70%–130% range. This gives phone users a substantially better whole-piece overview without changing the actual creative artifact.

## Change

Updated `property/js/marketing-studio-production-v2.js`.

The zoom handler now detects `max-width: 700px` through `matchMedia` and applies mobile-only bounds:

- mobile minimum zoom: 60%;
- mobile maximum zoom: 120%;
- desktop minimum remains 70%;
- desktop maximum remains 130%.

The existing zoom percentage display, recentering, front/back state, canvas CSS variable, and `wdd:zoom-changed` event remain unchanged.

## Verification evidence

Source re-read after the write confirms:

1. The creative runtime still initializes at 100% and continues to render the same authentic postcard canvas and front/back geometry.
2. The zoom handler now branches on `window.matchMedia('(max-width: 700px)')` and uses 0.6–1.2 only on mobile while preserving 0.7–1.3 on desktop.
3. The existing mobile audit stylesheet still constrains the creative surface to a contained pan/zoom viewport, with a 560px canvas and a 520px narrow-phone canvas rather than altering print-art geometry.
4. Zoom controls remain 44px+ touch targets from the dedicated mobile audit stylesheet.
5. JavaScript syntax for the responsive bound expression was separately validated with Node before this run was closed.
6. No Supabase schema/data, auth, billing, approval semantics, campaign data, print geometry, or desktop styling was changed.

## Desktop-isolation result

**PASS.** The only behavioral difference is guarded by `matchMedia('(max-width: 700px)')`. Desktop retains the original 70%–130% zoom limits and all existing creative behavior.
