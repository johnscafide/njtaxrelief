What you can automate

The connector is intentionally split into instant triggers, property searches and governed actions.

TRIGGERS

React to Watchdog events

Property Signal Changed
Start a workflow when a governed property signal materially changes.

Watchlist Alert
Route Watchlist alerts into communication or task systems.

Report Ready
Continue a workflow when a requested Watchdog report is ready.

Intelligence Finding Created
Use approved Intelligence findings as a workflow trigger when the connection has Intelligence read permission.

SEARCHES

Find governed property context

Find Property
Resolve a property through Watchdog's public property contract.

Find Governed Property Snapshot
Retrieve an approved property snapshot for downstream workflow logic.

Owner/person fields are not part of the public Zapier property contract, and missing values remain missing rather than being invented.

ACTIONS

Send work back to Watchdog

Add / Remove Property from Watchlist
Keep a user's monitored set synchronized with workflow decisions.

Send CRM Context to Watchdog
Attach normalized workflow context without turning CRM data into property truth.

Run Watchdog Intelligence for Property
Queue an approved Intelligence model using the user's normal plan, quota and idempotency rules.

Production API reference

The Zapier connector uses one HTTPS production endpoint with explicit action contracts. The API key belongs only in authentication, never in a trigger, search or action field.

ENDPOINTPOST /functions/v1/zapier-apiProduction host: uvkvaxljhhngydvlrzom.supabase.co. Requests and responses use JSON.
AUTHENTICATIONX-Watchdog-KeyUse a self-service key beginning with wdg_zap_. Revoked or unknown keys return HTTP 401.
PLAN BOUNDARYPro+ or TeamsConnector access is server-enforced. An ineligible account returns HTTP 403 before the requested action runs.
CONNECTION LABELKey label, never key secretZapier identifies the connection using the non-secret label returned by Watchdog's authentication test.

Authentication and trigger actions

These actions support account validation and the complete REST Hook lifecycle.

AUTH

auth.test

Scope: zapier.auth

Returns the connected Watchdog account ID, plan, non-secret key label and granted capabilities. The key itself is never returned.

HOOK

trigger.subscribe

Scope: triggers.manage. Intelligence findings also require intelligence.read.

Inputs: event_type, Zapier-provided public HTTPS target_url.

Creates an isolated Watchdog subscription for that Zap and returns its subscription ID and status.

HOOK

trigger.unsubscribe

Scope: triggers.manage.

Input: subscription_id.

Revokes only the subscription owned by the same user and integration key, and cancels its pending delivery work.

SAMPLE

trigger.sample

Scope: triggers.manage. Intelligence findings also require intelligence.read.

Input: event_type.

Returns recent governed events for the connected account, or a publication-safe fallback sample when no real event exists yet.

Supported trigger event types

REST Hook subscriptions reject event types outside this production allowlist.

EVENTproperty.signal.changedA governed property signal materially changed.
EVENTwatchlist.alertA Watchlist alert is available for the connected account.
EVENTreport.readyA requested Watchdog report reached ready state.
EVENTintelligence.finding.createdA governed Intelligence finding was created. Explicit intelligence.read permission is required.

Property and Watchlist actions

Property reads use Watchdog-governed records. Missing property values remain null rather than being inferred.

SEARCH

property.find

Scope: property.read.

Inputs: either pams_pin or street-address query; optional town.

Returns up to 10 governed property matches with public parcel, location, assessment and tax fields.

SEARCH

property.snapshot

Scope: property.read.

Input: required pams_pin.

Returns the governed property snapshot and latest Watchdog Score when available. Owner/person fields are excluded.

ACTION

watchlist.add

Scope: watchlist.write.

Inputs: required pams_pin; optional nickname and notes.

Adds or updates the property in the connected account's Watchlist.

ACTION

watchlist.remove

Scope: watchlist.write.

Input: required pams_pin.

Removes that property from the connected account's Watchlist and reports whether a row was removed.

CRM context and Intelligence actions

External CRM context stays separate from governed property truth. Intelligence jobs remain subject to plan limits, supported-model controls and idempotency.

ACTION

crm.context.attach

Scope: crm.context.write.

Required: external_contact_id.

Optional: pams_pin, property address, contact name/email/phone, lead stage, relationship, last activity timestamp and tags.

Stores normalized user-authorized workflow context. It does not replace or silently edit governed Watchdog property facts.

ACTION

intelligence.run

Scope: intelligence.run.

Required: pams_pin, model_key. Optional stable source_event_id improves retry idempotency.

Supported models: assessment_anomaly and property_change_priority.

Queues one governed property Intelligence job subject to daily and concurrent plan quotas. Unsupported models are rejected.

HTTP behavior

Errors are returned as JSON with a human-readable error field. Zapier should surface the failure rather than silently treating it as success.

400Invalid requestMissing required input, unsupported trigger event, invalid JSON or unknown action.
401Authentication failedThe Watchdog Zapier key is missing, invalid or revoked.
403Permission deniedThe account plan or key scope does not permit the requested operation.
404Resource not foundThe requested governed property or owned subscription was not found.
409Governed operation rejectedAn unsupported or unavailable governed Intelligence model was requested.
429Plan quota reachedThe daily or concurrent Intelligence limit for the connected plan was reached.
503Service dependency unavailableA required Watchdog database or service operation could not complete safely.

Troubleshooting

Most connection issues fall into a small number of categories.

Authentication fails

Create a new key from Integration Center and reconnect the Watchdog account. Do not email or paste a reusable key into support messages.

A trigger never fires

Confirm the Zap is enabled, the Watchdog key still has triggers.manage, and the event is enabled for that connection. Intelligence findings also require intelligence.read.

An Intelligence action is rejected

Confirm intelligence.run, a supported model, a valid governed property identifier, and available plan quota. Retrying the same external event should use a stable source event ID.
